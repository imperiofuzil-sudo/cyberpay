VexaPay para desenvolvedores

API PIX VexaPay

Cobranças, saques e consulta de status no backend.

Autenticação

API REST

Use as credenciais VexaPay somente no servidor. Nunca compartilhe Client Secret no navegador.

AuthorizationBearer SEU_CLIENT_SECRET
X-Client-IdSEU_CLIENT_ID
Base URLhttps://vexapay.site/api/v1

Endpoints principais

PIX
Criar cobrançaPOST /charges
Consultar cobrançaGET /charges/{id}
Criar saquePOST /payouts
Consultar saqueGET /payouts/{id}

Corpo da cobrança

JSON

Informe payer.name e payer.document (CPF). external_id é recomendado para evitar duplicidade.

{ "amount": 1.00, "external_id": "pedido-123", "payer": { "name": "Maria da Silva", "document": "52998224725" } }

Corpo do saque

JSON

Informe pix_key e pix_key_type: cpf, cnpj, email, telefone ou aleatoria. HTTP 202 significa que o saque foi aceito para análise.

{ "amount": 1.00, "pix_key": "financeiro@empresa.com", "pix_key_type": "email", "external_id": "saque-987" }

A API pode processar PIX real mesmo em sandbox. Consulte VEXAPAY_API.md para erros, webhooks e detalhes de integração.

Desenvolvedores

Webhooks VexaPay

Configure uma URL HTTPS no painel VexaPay e valide os eventos no servidor.

Endpoint deste projeto

HTTPS obrigatório
https://SEU_DOMINIO/api/webhooks/vexapay

Configure VEXAPAY_WEBHOOK_SECRET no servidor. A rota valida X-VexaPay-Signature sobre o corpo bruto.

Eventos

HMAC-SHA256
Cobrançaspix.charge.paid / pix.charge.cancelled
Saquespix.payout.paid / pix.payout.cancelled

A VexaPay não reenvia webhooks. Consulte GET /charges/{id} e GET /payouts/{id} como contingência.
